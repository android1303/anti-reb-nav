# Anti-Reb Nav — інструкції для Кодера (Claude Code)

Автомобільний навігатор для Android без GPS (умови РЕБ): Dead Reckoning — відстань зі швидкості OBD-II (ELM327), курс з гіроскопа телефона. React Native (Expo SDK 57) + нативний Kotlin-модуль Bluetooth. Повний контекст, архітектура, результати заїздів і правила — у Master Plan:

@docs/MASTER_PLAN.md

## Твоя роль

Ти — Кодер. Архітектор (Claude у проєкті на claude.ai) проєктує рішення, аналізує заїзди й видає завдання у форматі `TASK-<номер>`. Власник — Андрій: передає завдання, збирає APK, проводить заїзди.

- Виконуй завдання в межах його пунктів «Файли», «Зміни», «Не чіпати».
- Якщо завдання неоднозначне, суперечить Master Plan або коду — зупинись і запитай, не вгадуй.
- Якщо бачиш баг або ризик поза завданням — не виправляй мовчки, опиши в розділі «Питання до Архітектора» у REPORT.
- Завдання без номера TASK від Андрія виконуй так само, але в REPORT познач «без TASK».

## Незмінні правила (коротко; повністю — розділ 4 Master Plan)

1. Логіку ядра в `telemetry.js` і константи калібрування змінюй **лише** за явним TASK, що це вказує.
2. Гіроскоп `expo-sensors` віддає рад/с; ядро працює в °/с.
3. Не визначати нерухомість за акселерометром/гіроскопом; нерухомість = свіжий OBD і швидкість 0.
4. Не пом'якшувати пороги ZUPT без перевірки відтворенням.
5. У лог завжди пишуться сирі дані датчиків — не видаляй і не перейменовуй сирі колонки CSV.
6. Під час запису нічого важкого в потоці JS (синхронізація, великі JSON).
7. Збірка APK — через GitHub Actions (`assembleRelease`), не EAS.

## Перевірка

- Будь-яка зміна `telemetry.js` → відтворення на всіх заїздах із `field_tests/data/` (якщо є) до і після:
  ```
  node tools/replay/replay.mjs field_tests/data/<заїзд.csv> replay_tmp.csv
  python tools/replay/compare.py replay_tmp.csv
  ```
  На Windows — python, на Linux/macOS — python3. replay_tmp.csv не комітити (*.csv в .gitignore). Залежності: npm install; python -m pip install --user numpy pandas.
  Результати (кінцева похибка, RMS) — у REPORT. Якщо похибка зросла, а TASK цього не передбачав — зупинись і повідом.
- Синтаксис/збірка JS: `npx esbuild <файл> --bundle=false` або повна збірка, якщо доступна.
- Нові npm-пакети з нативним кодом — через `npx expo install <пакет>` (правильна версія для SDK 57).
- Якщо інструмент недоступний у твоєму середовищі (node, npm, python) — прямо напиши це в REPORT і що саме лишилося неперевіреним. Не пиши «перевірено», якщо не запускав.

## Документація

- Кожен TASK, що змінює поведінку, оновлює `docs/MASTER_PLAN.md` у тому ж коміті: історію змін (розд. 10), константи (розд. 3), backlog (розд. 7), останній номер TASK (розд. 9).
- Версія ядра в заголовку `telemetry.js` (vN) і в Master Plan мають збігатися.

## Коміти

- Один TASK = один коміт (або PR). Повідомлення: `TASK-<номер>: <суть>`.
- Не комітити секрети, `node_modules`, згенеровані APK. Сирі CSV заїздів у git не комітяться (репозиторій публічний, у CSV GPS-трек); локально вони лежать у field_tests/data/ (в ігнорі).

## Звіт після кожного завдання

Завжди завершуй роботу блоком коду, який Андрій передасть Архітектору без правок:

```
REPORT TASK-<номер>
Статус: done | partial | blocked
Коміт: <hash> (<гілка>)
Змінені файли: <перелік>
Що зроблено: <коротко по пунктах TASK>
Перевірка: <що запускав і результат; replay: до X м → після Y м>
Не перевірено: <що і чому>
Відхилення від TASK: <немає | що і чому>
Питання до Архітектора: <немає | перелік>
```

## Структура

| Шлях | Що це |
|---|---|
| `App.js` | UI, датчики, цикл ядра 20 Гц, keep-awake |
| `telemetry.js` | Ядро DR, ZUPT, зберігання, синхронізація, експорт CSV |
| `obdScanner.js` | ELM327: ініціалізація, опитування `010D`, парсинг |
| `exportService.js` | Експорт з Firestore |
| `android/.../Elm327Module.kt` | Нативний Bluetooth RFCOMM |
| `tools/replay/` | Відтворення заїздів і порівняння з GPS |
| `field_tests/` | Звіти заїздів (`<дата>_<назва>.md`), дані в `data/` |
| `docs/MASTER_PLAN.md` | Єдине джерело правди |
| `docs/prompts/ARCHITECT.md` | Інструкції Архітектора (копія Project instructions) |
| `docs/OWNER_GUIDE.md` | Інструкція Власника |
