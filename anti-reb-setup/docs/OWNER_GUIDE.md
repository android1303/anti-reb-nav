# Інструкція Власника (Андрій)

Ти — власник проєкту й системний інтегратор. Архітектор (Claude у проєкті на claude.ai) думає і перевіряє, Кодер (Claude Code) пише код у репозиторії. Твоя робота — рішення, заїзди, збірка і передача артефактів між ними. Код руками не правиш.

## 1. Одноразове налаштування

**Репозиторій GitHub**
1. Усі файли проєкту в репозиторії, структура — як у таблиці в `CLAUDE.md`.
2. Старі копії (`Master_plan_v13.txt`, «новий MASTER PLAN v13.md», файли з `Downloads`) видалити, щоб не було двох версій правди.

**Комп'ютер (для Claude Code)**
1. Claude Code: десктопний застосунок Claude (вкладка Code) або CLI. Відкрити теку репозиторію.
2. Встановити Node.js LTS і Python 3 з `pandas`, `numpy`, `matplotlib` — без них Кодер не може перевіряти збірку й відтворювати заїзди.
3. У теці проєкту: `npm install`.

**Проєкт на claude.ai (Архітектор)**
1. Project instructions: вставити повний текст `docs/prompts/ARCHITECT.md`.
2. Project knowledge: видалити всі старі завантажені вручну файли. Додати «+» → GitHub → свій репозиторій і вибрати: `CLAUDE.md`, `docs/`, `App.js`, `telemetry.js`, `obdScanner.js`, `exportService.js`, `Elm327Module.kt`, `tools/`, `field_tests/*.md`, `package.json`. Не вибирати `node_modules`, `android/build`, великі CSV.
3. Синхронізація бази знань з GitHub **ручна**: після кожного коміту натискати іконку «Sync» у базі знань проєкту. Без цього Архітектор бачить старий код.
4. Усі розмови про проєкт — лише всередині цього проєкту. Одна розмова = одна тема (один заїзд, одна задача).

**Необов'язково: автоматизація через GitHub (рівень 2)**
1. У Claude Code виконати `/install-github-app` (потрібні права адміністратора репозиторію). Для роботи GitHub Action потрібна автентифікація — API-ключ Anthropic або токен підписки; актуальні варіанти — у документації Claude Code GitHub Actions.
2. Після цього TASK можна вставляти в GitHub Issue (шаблон «TASK від Архітектора») і писати коментар `@claude виконай цей TASK за правилами CLAUDE.md`. Claude відкриє PR; ти переглядаєш і зливаєш.
3. Workflow збірки APK у GitHub Actions — запуск на push у `main`, APK як артефакт збірки.

## 2. Робочий цикл

1. **Заїзд** за протоколом (Master Plan, розд. 7). Експорт CSV. Назва: `<дата>_<маршрут>.csv`.
2. **Архітектор:** нова розмова в проєкті, CSV + повідомлення:
   ```
   Заїзд <дата>, <маршрут>. APK: ядро v<N>, коміт <hash>.
   Нотатки: <що помітив у дорозі: розриви OBD, де стояв, де телефон рухався>.
   Проаналізуй за стандартною процедурою.
   ```
3. **Архітектор видає TASK** (блок коду). Якщо не згоден або є питання — обговорюєш у тій же розмові.
4. **Кодер:** копіюєш блок TASK у Claude Code без змін (або в GitHub Issue для рівня 2).
5. **Кодер повертає REPORT.** Перевіряєш, що статус `done` і коміт запушено.
6. **Sync** бази знань у проєкті → вставляєш REPORT Архітектору в ту ж розмову:
   ```
   REPORT від Кодера нижче. Sync зроблено. Прийми роботу.
   <блок REPORT>
   ```
7. **Архітектор приймає** або видає TASK з виправленням.
8. **Збірка APK** через GitHub Actions → встановлення → наступний заїзд.

## 3. Правила

- Перед питанням Архітектору про код — завжди Sync.
- Не виправляй код і не «підкручуй» константи руками. Будь-яка зміна — через TASK, щоб вона пройшла перевірку і потрапила в Master Plan.
- Якщо Кодер не погоджується з TASK — перенеси його аргумент Архітектору дослівно. Рішення фіксується в Master Plan.
- Якщо Архітектор або Кодер пишуть «перевірено» — питай, чим саме. Неперевірене має бути позначене.
- Отриманий від будь-кого файл перед заміною в проєкті перевір: версія в заголовку і розмір мають відповідати опису.
- Сирі CSV зберігай усі. Вони — головний актив проєкту: кожну нову версію ядра можна перевірити на всіх старих заїздах.

## 4. Чек-лист перед заїздом

- [ ] APK зібраний з останнього прийнятого коміту; номер версії ядра записаний.
- [ ] Телефон жорстко закріплений, на зарядці, яскравість знижена.
- [ ] OBD підключено, на екрані «Онлайн», швидкість оновлюється.
- [ ] Еталонний GPS увімкнено.
- [ ] Запис → 60 с стоянки із заведеним двигуном, нічого не торкаючись.
- [ ] Маршрут зі стоянками ≥ 10 с і поворотами в обидва боки.
- [ ] Наприкінці 30–60 с стоянки → зупинити запис кнопкою → експорт CSV.
- [ ] Записати нотатки: що відбувалося в дорозі.
